# `ffsgen` A tool for generating initial contents for the "femto filing system"

## Intended audience
It is recommended that the reader be at least somewhat familiar with the usage of the Raspberry Pi Pico SDK (henceforth the SDK) and operation of the RP2040 & RP2350 microcontroller devices.

For *this* document to be of value, the reader should also be familiar with the design and operation of the "femto filing system" which is covered in [README_ffs.md](../../src/rp2_common/pico_ffs/README_ffs.md)

## Introduction
This document describes the usage of the "femto filing system" generator utility, hereinafter referred to as **`ffsgen`** and styled in lower-case.

## `ffsgen` Generating a initial filing system
Many embedded systems will require some "pre-programmed" configuration data to be present in flash when the system is first booted.

The `ffsgen` tool will construct and write a binary object file from a *list* of file IDs and their respective source files contained, in a config file.   The ffs object file can then be concatenated with the operating system payload, WiFi firmware etc. to allow programming in a single step.

It will also be possible to "dump" the ffs flash area from a "golden" device and use the contents to generate a initial ffs payload as would be generated by `ffsgen` but this is a much less "programmatic" approach!

## Building `ffsgen`

`ffsgen` is built as a standalone host tool using CMake.  From the `tools/ffsgen` directory:

```bash
cmake -B build
cmake --build build
```

The resulting `ffsgen` executable will be placed in the `build/` sub-directory.  You should copy this file into a directory in the path in your system if you want to be able to use it direct from the command line or a Makefile etc.

## Using `ffsgen`

### Invocation

```
ffsgen <config_file> <output_file> [chunk_size]
```

| Argument | Description |
|---|---|
| `config_file` | Path to the text configuration file describing the files to include (see below). |
| `output_file` | Path for the binary output blob.  This file must be programmed at the start of the (otherwise erased) ffs flash area. |
| `chunk_size`  | *Optional.*  Size of one ffs chunk in bytes.  Should be an integer multiple of the flash sector size (4096 bytes on all Pico boards) — `ffsgen` will warn, but still proceed, if it is not.  Defaults to 4096 bytes if omitted. |

### Configuration file format

Each non-blank line in the configuration file specifies one file to include, using the format:

```
<file_id>  <filename>
```

Lines beginning with `#` are treated as comments and ignored.  A minimal example:

```
# ffsgen configuration for my_project
0  wifi_config.bin
1  server_cert.pem
2  default_settings.bin
```

**Rules:**
- `file_id` must be a decimal integer in the range `0`–`254` (inclusive).
- Each `file_id` must be unique within the configuration file.
- `filename` may include a relative or absolute path.  Relative paths are resolved from the directory in which `ffsgen` is invoked.

### Output

`ffsgen` writes a single binary file of exactly `chunk_size` bytes (default: 4096 bytes), pre-filled with `0xFF` (the unprogrammed flash value) and then populated with the ffs chunk header followed by the specified files in the order they appear in the configuration file.

The output file is intended to be programmed directly into flash at the start of the ffs storage area, before the application is first run.  It can be concatenated with other firmware images (application binary, Wi-Fi firmware, etc.) and programmed in a single step using `picotool` or similar.

`ffsgen` prints a progress summary as it runs, reporting the file ID, source filename, data length, and remaining space in the chunk for each file added.  On success the final line reports the total number of bytes written to the output file.

### Notes

- The output represents only **one** ffs chunk.  At runtime, ffs manages two chunks internally; the second chunk starts as virgin (erased) flash and is prepared automatically by ffs on first use.
- If the accumulated file data (including file headers and alignment padding) will not fit within a single chunk, `ffsgen` will report an error and no output file will be written.
- The `chunk_size` supplied to `ffsgen` must match the chunk size that will be used at runtime, which is half the total flash area allocated to ffs.
